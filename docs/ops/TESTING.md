## Mock API (TST-04)

`VITE_API_MODE=mock` (Vitest and the standalone prototype) binds the HTTP binding (`api/http.ts`) to a replay of `frontend/src/api/mock/recorded.json` (`api/mock/replay.ts`): real responses of one demo scenario on the fixtures, recorded by `make record-mock` (`backend/tools/record_mock.py`: in-process app, inline jobs, a temporary workspace). A request is answered by the recording with the same method, path, query (paging dropped) and JSON body, else the same request with any body, else (GET) the same path without its query; anything else is a `not-recorded` problem (501). The mock computes nothing and a write changes no later answer, so component tests assert the request they send and leave the effect to the backend's tests. Re-record after an API change or a fixture change; the recording redacts the project id and every host path (`/data`, `/workspace`, `/derived`), and fails if a host path is left. `npm run mock:slices` writes the viewer placeholder's mid-slices (`api/mock/slices.json`). Vitest runs in `node` by default; files that need a DOM start with `// @vitest-environment jsdom`; the replay has no latency under Vitest.

Requirement IDs in tests (AUD-A4-01): a new or touched test names the IDs it covers in its docstring, `describe`/`test` title or header comment; `make trace` writes the ID → code/test citation report into `build/trace/` (a report, not a gate).

## Synthetic fixture dataset (TST-11)

Generated, not committed: `make fixtures` writes `.fixtures/synthetic/` (generator `backend/tools/make_fixtures.py`, oracle `expected.json`). It is small (64³–128³ int16 volumes, 3 labels as spheres/ellipsoids) and deterministic (fixed seed).
It contains `metadata.jsonl`, `phase.json`, `voi/voi_catalog.jsonl` and a legacy `.npy` VOI, plus **deliberate defects**:
missing SEG, shape mismatch, ambiguous phase, ambiguous side, duplicate identity, missing file, a `.mha` seg (`unsupported_format`), a VOI with `axis_order: yxz` (`ambiguous_axis_order`).
Every IMP-08 warning code must be produced by at least one fixture row.
P7b fixtures (generated, no real data): a synthetic DICOM series (pydicom, CT, with study/series descriptions and contrast times for the phase rules; one PHI-looking fake name to test anonymization), one Enhanced multi-frame file, a NIfTI-only folder in nnU-Net naming with a `labelsTr/` mask, a standalone label map, and NumPy pairs in `xyz` and `zyx` with sidecars.
Variables (VAR/ANA): no `group` field; case-level numeric study variables with ~50 % missing and one compositional pair; a `numeric-discrete` variable; vendor strings needing recode; one MRI scan; enough healthy cases (≥ 30) for group tests. Never copy values from real metadata into fixtures.

## E2E specs (Playwright, Chromium + Firefox)

All in `frontend/e2e/`, real backend on the fixtures (TST-05, TST-07 hook). Ports: `E2E_API_PORT`, `E2E_WEB_PORT`. Specs share `e2e/helpers.ts` (`api` through the web server's proxy, fixture paths, `importedProject`) and `e2e/openMode.ts`; the servers and temp folders are in `e2e/servers.ts`. The global teardown removes the run's temp workspace, derived and plugins folders unless `E2E_KEEP=1` (AUD-A0-05). Dev loop (AUD-A6-18): `make e2e SPEC=… PROJECT=…`, `make e2e-one SPEC=…` (one browser), `make e2e-servers` + `E2E_REUSE=1` (reuse running servers on fixed folders), `E2E_BUILD=1` (the production build through `vite preview`, for a nightly run).
