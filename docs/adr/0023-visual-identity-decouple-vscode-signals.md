# ADR-0023 Decouple literal VS Code/GitHub signals from the shell's visual identity
Status: Accepted · Date: 2026-09-25 · Refines: ADR-0010

**Context.** ADR-0010 chose a QuPath-style layout in a VS Code shell with GitHub Dark. Reviewed against a VS Code power user's eye, four specific signals in the shipped code read as literal VS Code/GitHub chrome rather than as a clinical tool's own identity, because they reuse VS Code/GitHub Primer patterns verbatim instead of only their density and palette: the 1 px per-plane viewport border tinted with the exact `--error`/`--warn`/`--ok` tokens (indistinguishable from a Git-diff or lint-state color); 11 px uppercase labels with `0.04em` tracking, identical to "EXPLORER"/"OUTLINE"/"PROBLEMS"; `.icon-btn[aria-pressed='true']`'s translucent-blue + inset-outline, identical to the search bar's "Match Case" toggle; and the monospaced `N/M` slice index, read as "Ln 12, Col 4". None of these are structural — they don't change any measurement, spacing, density or hover behavior — so they can change without the layout risk `AGENTS.md` warns against (R1 not implicated; no layout files touched).

A fifth signal considered in the visual review — an active-viewport focus ring copying VS Code's "active editor group" outline — turned out not to exist in the shipped code: `viewer.css:12` sets an unused `--vp-focus` custom property with no consumer, and no component tracks a "last-active viewport". There is nothing to decouple there, and adding a new active-viewport indicator now would be a feature addition outside this ADR's scope (decoupling existing signals, not designing new ones); left out of this decision.

**Decision.** Keep everything ADR-0010 decided (QuPath panes in VS Code shell regions, GitHub Dark palette, codicons + custom CT set, all structural metrics in `tokens.css`) unchanged. Retint/retext only these four signals:

1. **Viewport panel accent** (VW-04, `Viewport.tsx`): the plane color moves off the panel's 1 px border — which becomes a neutral `--border-muted` frame — onto an 8×8 px, 2 px-radius chip in the panel header (`.vp-swatch` retired in favor of `.vp-chip`, or repurposed as the chip). The three plane accents desaturate off the literal `--error`/`--warn`/`--ok` hexes: axial `#F85149` → `#CF6679`, sagittal `#D29922` → `#C9A23C`, coronal `#3FB950` → `#4F9D7C`. Crosshair lines, the slice slider's `accent-color` and any other VW-04 consumer follow the new values.
2. **Tracked uppercase labels** (sidebar header, `.section-title`, `.panel-tab`, and similar): drop `text-transform: uppercase` and `letter-spacing: 0.04em`; keep the same box height, size and `--fw-semibold` weight — sentence case only.
3. **Pressed toggle** (`.icon-btn[aria-pressed='true']`, `.vp-3d-tools .icon-btn[aria-pressed='true']`): replace `background: var(--bg-selected); box-shadow: inset 0 0 0 1px var(--focus)` with a darker "pressed" texture (a darker flat background plus a subtle inset shadow), no blue. `--focus`/`--accent` blue stays reserved for live interaction (dragging, measuring), never a resting toggle state.
4. **Slice index** (`.vp-index`, `viewer.sliceOf`): drop `ui-monospace` for the UI font; change the `{{index}}/{{total}}` separator to `{{index}} · {{total}}`.

Everything else — 26 px hover-only icon buttons, toolbar density (2 px gap, 8 px margin, 1×18 px separators), the title bar's menus/search/layout toggles, all `--h-*`/`--w-*` metrics, codicon usage, GitHub Dark's remaining tokens, the unused `--vp-focus` variable — is unchanged and out of scope for this ADR.

**Consequences.** + Removes the strongest "this is a VS Code editor group" tells without touching layout, density or any interaction (no re-test of hit areas, drag, resize); + GitHub Dark and codicons stand exactly as ADR-0010 decided, so this is additive, not a reversal. − The plane identity signal moves from the panel's own border to a new small element (header chip), so `Viewport.tsx` and `viewer.css` gain a small amount of markup. − `VW-04`'s color values and `UI_SHELL.md`'s theme-tokens table both need updating in lockstep (tracked below; no new custom properties are introduced, only existing `--plane-*` values and CSS usage change).

**Rejected.** Adding a new active-viewport focus/dim treatment (nothing to decouple today — see Context; would be a new feature, not a decoupling). Redrawing the icon set to diverge from literal codicons (bigger surface, second pass — deferred, not part of this ADR). Reworking the title bar's menus/search/command-center composition (would touch layout and title-bar structure, out of scope here; revisit separately if still needed after this pass). Renaming the `--plane-*`/`--focus`/`--bg-selected` custom properties (breaks "one fact, one place" for no benefit — only their values/usage at these four call sites change).

**Doc updates required:** `frontend/VIEWER.md` VW-04 (colors, border ownership); `frontend/UI_SHELL.md` theme-tokens section (note the four retinted/retexted signals and point to this ADR).
